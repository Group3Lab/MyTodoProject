# 常用 Markdown 语法

面向 c-lab 组员：写 README、说明文档、PR 描述时够用的一份速查表。

配着看：[../README.md](../README.md)（提交信息前缀表）、[pr流程说明书.md](./pr流程说明书.md)。

> **一句话原则**：Markdown 就是纯文本加上几个记号。**记号前后留空行 / 空格**，能避开 90% 的"为什么没生效"。

---

## 一、速查表

| 想要的效果 | 写法 | 备注 |
| --- | --- | --- |
| 一级标题 | `# 标题` | 一个文件只用一个 |
| 二级标题 | `## 标题` | 往上还有三级、四级…… |
| 加粗 | `**文字**` | |
| 斜体 | `*文字*` | |
| 粗斜体 | `***文字***` | |
| 删除线 | `~~文字~~` | |
| 行内代码 | 反引号包住 | 反引号是键盘左上角那个键 |
| 代码块 | 三个反引号包起来 | 开头那行可以写语言名 |
| 无序列表 | `- 内容` | `-` 或 `*` 或 `+`，全文统一 |
| 有序列表 | `1. 内容` | 序号全写 `1.` 也没关系 |
| 任务列表 | `- [ ]` / `- [x]` | 待办和已完成 |
| 引用 | `> 内容` | |
| 链接 | `[文字](网址)` | |
| 图片 | `![说明](图片路径)` | 开头多个 `!` |
| 表格 | 用 `\|` 分隔，第二行写分隔行 | 见第五节 |
| 分隔线 | `---` 单独一行 | 上面要空一行 |
| 换行 | 行尾敲两个空格，或空一行 | 直接回车不算换行 |
| 转义 | 在符号前加 `\` | 例如 `\*` 显示星号本身 |

## 二、标题

```markdown
# 一级标题（文件标题，一般只写一个）
## 二级标题（大章节）
### 三级标题（小节）
#### 四级标题（再往下）
```

`#` 后面**要有一个空格**，`#标题` 在某些编辑器里不生效。

---

## 三、强调与代码

```markdown
**加粗**  *斜体*  ***粗斜体***  ~~删除线~~
```

行内代码适合写命令名、文件名、变量名：用反引号包住写成 `` `git push` ``。

代码块用三个反引号，**开头那行写上语言名**才有语法高亮：

````markdown
```python
def add(a, b):
    return a + b
```

```bash
git add .
git commit -m "docs: 补充说明"
```
````

> 小技巧：如果代码块里还要放三个反引号，外层就用**四个**反引号包起来。

## 四、列表

```markdown
- 第一项
- 第二项
  - 缩进两个空格就是子项
- 第三项

1. 第一步
2. 第二步
3. 第三步

- [ ] 还没做的事
- [x] 已经做完的事
```

**注意点：**

- 符号和文字之间**要有空格**：`- 内容` 对，`-内容` 很多编辑器不认
- 有序列表的序号随便写，渲染时会自动从 `1.` 排起，但建议老实递增
- **列表和上下段落之间空一行**，否则可能被吸进去

## 五、表格

```markdown
| 前缀 | 用途 | 例子 |
| --- | --- | --- |
| `feat` | 新功能 | `feat: 新增冒泡排序练习` |
| `fix` | 修 bug | `fix: 修复数组越界` |
```

规则：

- 第二行是**分隔行**，必须有，否则不成表格；`| --- |` 是最常用的写法
- 对齐方式靠分隔行里的冒号：`| :--- |` 左对齐、`| :---: |` 居中、`| ---: |` 右对齐
- 单元格里想写 `|` 本身，前面加反斜杠：`\|`
- 写不整齐也能渲染，但**源码对齐方便别人看**

> 表格里写代码同样用反引号，像上面 `feat` 那样。

---

## 六、引用、分隔线与换行

```markdown
> 这是一段引用
>
> > 引用还能套引用
```

引用常用来写提示和警告：

```markdown
> **注意**：不要 `git push -f`。
```

分隔线：单独一行写 `---`（**前面空一行**，否则可能被当成标题下划线）。

换行有两种：

| 写法 | 效果 |
| --- | --- |
| 行尾敲**两个空格**再回车 | 换行，行距不变 |
| 中间**空一整行** | 另起一段，段落之间会有间距 |

## 七、链接与图片

```markdown
[GitHub](https://github.com)
[仓库内的文档](../README.md)
[仓库外的文档](./pr流程说明书.md)
[文档里的某一段](./pr流程说明书.md#一、一句话版本)
```

- 链接到**本仓库**的文件，用相对路径，别人 clone 下来也能点开：同目录用 `./xxx.md`，上一级用 `../xxx.md`
- `#` 后面接标题就是锚点，能直接跳到某一节

图片比链接多个 `!`：

```markdown
![任务统计图](./chart.png)
```

- **相对路径**以当前 md 文件所在位置为起点。本文档在 `Learn/` 里，所以 `./pr流程说明书.md` 指向同目录的文档，指仓库根目录的 README 要写 `../README.md`
- 路径里有空格或中文，建议用尖括号包起来：`![图](<./我的 图.png>)`

## 八、HTML 兜底

Markdown 里**可以直接写 HTML**，实在找不到记号时用得上：

```html
<br>                      <!-- 强制换行 -->
<div align="center">居中</div>
<span style="color:red">红字</span>
```

GitHub 会过滤掉一部分 HTML（比如 `<script>`），但常见的标签能用。

> 本项目导出报告用的是 HTML 文件，和这里是两回事：报告是**浏览器直接打开**的网页，这里的 HTML 是**塞进 md 里的片段**。

## 九、写文档的几条建议

1. **先写目录结构再填内容**：标题层次 `#` → `##` → `###`，别从 `#` 直接跳到 `####`
2. **一个文件一个主题**：像 [pr流程说明书.md](./pr流程说明书.md) 那样，标题就是它讲的事
3. **多用表格**：前缀表、命令速查表这种"一对一"的内容，表格比段落清楚
4. **命令行例子用 `bash` 代码块**，别人能一键复制
5. **符号前后留空**：`# `、`- `、`> `，这条能省掉大部分排查时间
6. **提交前预览**：VS Code 里 `Ctrl+Shift+V` 打开预览，确认渲染没问题再提交

## 十、常见问题

### Q1: 为什么我的换行没生效？

单个回车在 Markdown 里只是"空格"，要**行尾两个空格**或**空一整行**才是换行。

### Q2: 为什么表格没渲染出来？

多半是**漏了第二行分隔行** `| --- | --- |`。

### Q3: 为什么 `#` 标题不生效？

`#` 后面漏了空格。要写 `# 标题`，不是 `#标题`。

### Q4: 为什么 `*` 显示成了斜体，我只想打一个星号？

在符号前加反斜杠转义：`\*`。表格里的 `|` 也一样，写 `\|`。

### Q5: 代码块里怎么再放三个反引号？

外层用四个反引号包起来，像本文第三节那样。
