# 添加新功能指南

本文档面向组员，说明如何在现有架构下添加新的菜单功能。

## 一、架构概览

```
MyTodo/
├── core/
│   ├── menuModule/          # 菜单系统（已完成，无需修改）
│   │   ├── menu.py          # 菜单抽象基类
│   │   ├── menuSystem.py    # 菜单管理系统
│   │   └── menuFactory.py   # 菜单工厂（需要在这里注册新菜单）
│   └── taskModule/          # 任务系统（已完成，可扩展）
│       ├── task.py          # 任务数据模型（数据结构负责人，这里是要长期更改的地方）
│       └── taskSystem.py    # 任务管理系统（数据结构负责人，这里是要长期更改的地方）
├── menus/                   # 具体菜单实现（你的工作区，注意目录名是小写）
│   ├── MenuA.py             # 示例：测试菜单（无依赖注入）
│   ├── AddTaskMenu.py       # 示例：添加任务
│   ├── ViewTasksMenu.py     # 示例：查看任务
│   └── DeleteTaskMenu.py    # 示例：删除任务
└── src/
    └── main.py              # 主程序（无需修改）
```

## 二、添加新功能的三步流程

### 步骤 1：在 `menus/` 文件夹创建新菜单类

在 `menus/` 文件夹下创建一个新的 `.py` 文件，例如 `CompleteTaskMenu.py`（注意目录名 `menus` 是小写，导入时也必须写成小写）。

**模板代码：**

```python
"""
[功能描述]
使用依赖注入获取 TaskSystem 实例
"""

from core.menuModule.menu import Menu
from core.taskModule.taskSystem import TaskSystem


class YourMenuName(Menu):
    def __init__(self, task_system: TaskSystem):
        super().__init__(
            "菜单名称",           # 显示在主菜单的标题
            "菜单功能简介"        # 显示在主菜单的说明（可以多行）
        )
        self.__task_system = task_system

    def execute(self) -> int:
        """菜单的核心逻辑"""
        try:
            # 在这里实现你的功能
            # 可以使用 self.__task_system 的所有方法
            
            return 0  # 成功返回 0

        except Exception as e:
            print(f"[错误] {e}")
            return -1  # 失败返回 -1 （外部会处理错误码不必担心）
```

**如果新菜单不需要访问数据：** 参照 [MenuA.py](../menus/MenuA.py) 的写法，`__init__` 不接收 `task_system`，调用 `super().__init__(...)` 后直接写 `execute()` 即可，同时注册时也不传参数（见步骤 2）。

### 步骤 2：在 `menuFactory.py` 注册新菜单

打开 `core/menuModule/menuFactory.py`，做两处修改：

**① 在文件顶部导入你的菜单类**（和已有的导入写在一起，路径同样是小写 `menus`）：

```python
from menus.MenuA import MenuA
from menus.ViewTasksMenu import ViewTasksMenu
from menus.AddTaskMenu import AddTaskMenu
from menus.DeleteTaskMenu import DeleteTaskMenu

from menus.YourMenuName import YourMenuName  # 添加这一行
```

**② 在 `_register_menus()` 方法中注册**（注意注册顺序就是实际菜单显示顺序）：

```python
@staticmethod
def _register_menus(menu_sys: MenuSystem, task_system: TaskSystem) -> None:
    # 功能菜单
    menu_sys.register(MenuA())              # 不需要数据的菜单直接实例化
    menu_sys.register(ViewTasksMenu(task_system))
    menu_sys.register(AddTaskMenu(task_system))
    menu_sys.register(DeleteTaskMenu(task_system))
    menu_sys.register(YourMenuName(task_system))  # 添加这一行
```

### 步骤 3：运行测试

在项目根目录运行：

```bash
python src/main.py
```

你的新功能会自动出现在菜单列表中。

## 三、TaskSystem 提供的方法

你可以在菜单的 `execute()` 方法中使用 `self.__task_system` 调用以下方法：

| 方法 | 说明 | 返回值 |
|------|------|--------|
| `add(title: str)` | 添加新任务 | `Task` 对象 |
| `get_by_index(idx: int)` | 获取指定索引的任务副本（只读） | `Task` 对象或 `None` |
| `delete(idx: int)` | 删除指定索引的任务 | `bool`（成功/失败） |
| `get_task_count()` | 获取任务总数 | `int` |

**注意：** 索引从 `0` 开始，但用户看到的编号从 `1` 开始，需要转换：`user_input - 1`

**注意：** `_get_by_index()` 是内部方法，返回的是内部引用（可直接改到数据），不要在自己的菜单里调用它。只读数据请用 `get_by_index()`。

**已完成但暂未启用：** `update_completed(idx, status)` 和 `Task.is_completed` 目前在 `taskSystem.py`、`task.py` 中被注释掉了，等"完成状态"需求落地后再放开，当前不要调用。

## 六、常见问题

### Q1: 菜单编号是如何分配的？
A: 菜单编号由 `MenuSystem` 自动分配，按照注册顺序从 `1` 开始递增。你只需关注注册的先后顺序。

### Q2: 如何获取用户输入？
A: 在 `execute()` 方法中使用 `input()` 函数：
```python
user_input = input("提示信息: ").strip()
```

### Q3: 如何处理非法输入？
A: 使用 `try-except` 捕获异常，并返回 `-1` 表示失败：
```python
try:
    num = int(user_input)
except ValueError:
    print("[错误] 输入无效")
    return -1
```

### Q4: 可以修改 `core/` 目录下的文件吗？
A: 如果需要扩展 `TaskSystem` 的功能（如添加搜索、筛选方法），可以修改 `core/taskModule/taskSystem.py`。但不要修改 `core/menuModule/` 中的文件。

### Q5: 多个菜单可以共享数据吗？
A: 可以。所有菜单通过依赖注入共享同一个 `TaskSystem` 实例，因此在一个菜单添加的任务可以在另一个菜单中看到。

### Q6: 菜单里出现一个叫 `MenuA` 的是什么？
A: 那是组长留的测试菜单（[MenuA.py](../menus/MenuA.py)），用来验证菜单系统能否正常注册和显示，不需要可以不管它。
